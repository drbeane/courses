## Connectors

A **connector** lets an agent reach an outside service:

- Calendar, email, and cloud storage such as Google Drive or OneDrive
- Course tools, databases, and project trackers

Instead of you copying information into the chat, the agent fetches it, and can act on the service too.

Most connectors are built on **MCP**, the Model Context Protocol.

---

## MCP, as a User

- MCP is an **open standard** for connecting AI to tools and data, supported by many vendors.
- So one connector can work across many AI apps, instead of each app building its own.
- A connector exposes **tools**, which are actions like "create event," and **resources**, which are data like a list of files.

We'll build one in week 12.

---

## How the Model Picks a Tool

- Each tool has a short **description** written by whoever built the connector.
- All the descriptions sit in the model's context, alongside your request.
- When your request matches one, the model calls that tool with the inputs it needs.

It's the tool-use loop from week 6, now reaching outside your computer. Each connector you add also adds descriptions to the context.

---

## Connecting a Service

1. Find the connector in settings
2. Sign in **on the service's own page**
3. Read the **permission screen**
4. Approve

After that the agent acts **as you**: anything it does on the service looks like you did it.


---

## Read vs Write Permissions

| Read | Write |
|---|---|
| See your calendar | Create events |
| Read email | **Send** email |
| List files | Delete files |

**Grant the least you need.**

Scope matters too: one folder, or the whole drive?

---

## What It Adds, What It Costs

| Adds | Costs |
|---|---|
| Real, current data | The agent sees private material |
| No copy and paste | Outside content enters the context |
| Tasks across services | Mistakes land where others see them |

A wrong answer in chat stays in the chat. A wrong action through a connector lands in someone's inbox or calendar.

---

## Keep Your Connections Tidy

- Connect what the current work needs, not everything you might someday use.
- Review the list of connections a few times a year.
- Disconnect what you no longer use. An idle connection is still access.
- Connect only accounts you own, never a shared or borrowed login.
