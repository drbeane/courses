# Standing Instructions
### Week 7
COSC-300/500 Applied AI Essentials

---

## The Problem

You keep typing the same context at the start of every task:

- who you are and what the work is for
- how the project or folder is organized
- what format you want results in
- what the agent must never do

Each time you forget a line, the agent guesses. **Write it down once.**

---

## Levels of Standing Instructions

| Level | Applies to | Example |
|---|---|---|
| Global | Everything you do | "Use US spelling. Be brief." |
| Project | One project or folder | "This is my thesis. Cite in APA." |
| Instruction file | One folder or repository | `AGENTS.md`, `CLAUDE.md` |

All the levels that apply are loaded together. Put each rule at the narrowest level where it's always true.

---

## Instruction Files

- An instruction file is a Markdown file that **lives with the work**, in the folder itself.
- The agent reads it when it starts working in that folder.
- It travels with the folder, so it can be version-controlled and shared with a team.
- **AGENTS.md** is a cross-vendor convention read by many coding tools.
- **CLAUDE.md** is Claude Code's own file.


---

## What One Looks Like

```markdown
# Coursework folder

## Layout
- One subfolder per course
- `inbox/` is where new downloads land

## Conventions
- File names: `YYYY-MM-DD - Course - Title`

## Rules
- Never delete a file. Move it to `archive/`.
- If unsure which course, leave it in `inbox/`.
```

Three parts: what this folder is, its conventions, and the rules the agent must follow.

---

## Writing Instructions That Get Followed

- Be **specific**: "file names start with the date" beats "name files sensibly."
- Say **why**, when it isn't obvious, so the agent can handle cases you didn't list.
- Keep it **short**: it's read on every task, and long files bury the important rules.
- Leave out what the agent can see for itself, like the list of files.
- Don't shout. Capital letters don't make a rule stick.
- No secrets: passwords and keys don't belong in a shared file.

---

## Standing Instructions vs One Brief

| Standing | One brief |
|---|---|
| True every time | True for this task |
| Folder layout, conventions | Today's goal |
| Style and format rules | This deliverable's audience |
| Things never to do | This task's constraints |

Would you want it to apply next week too? Then it's a standing instruction.

---

## Test and Revise

- Add one rule you can **see** working, and run a small task to compare before and after.
- If you've corrected the same thing twice, **add it to the file**.
- Prune rules that no longer apply, so the ones that matter stand out.

Instructions make a rule likely, not certain. Keep approvals and backups.
