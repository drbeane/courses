# From Chat Window to Coding Assistant
### Week 9
COSC-300/500 Applied AI Essentials

---

## No Coding Experience Assumed

You won't be graded on writing code.

You **will** learn to:
- specify software work clearly enough that an assistant can build it
- supervise the assistant while it works, in small, reviewable steps
- check the result by running it, testing it, and asking for explanations

These are the same skills as weeks 6–8, applied to a project folder full of code.

---

## Why This Is in the Course

Small, useful software is now within reach of people who don't program: a tracker, a calculator, a page for a club.

**Vibe coding** means describing what you want and accepting whatever comes back, without reading it.

That's fine for a quick personal tool. It's not fine when the program has to be correct, keep working, or be trusted by someone else.

---

## A Few Terms

| Term | Plain meaning |
|---|---|
| **Source code** | A program's instructions, as text files |
| **Repository** | A project folder with its history |
| **Dependency** | Someone else's code the project uses |
| **Test** | A small program that checks the main one |
| **Bug** | A mistake that makes it do the wrong thing |

---

## Two Facts About Code

**Code is exact.**
One wrong character and it may not start, or may quietly compute the wrong number. Unlike an essay, "close enough" doesn't work.

**Code can be checked by running it.**
You don't have to judge whether it looks right. You can run it, try inputs, and see what it does.

---

## Coding in a Chat Window

- Paste code in, copy code out
- Fine for one small file
- Breaks down when:
  - the project has many files
  - you need to run it
  - you need to test it
  - you need to undo a change

You become the messenger in every round.

---

## A Coding Assistant in the Environment

It has access to:

- **The repository**: every file in the project, not just the one you pasted
- **The terminal**: it can run the program, install what it needs, and run tests
- **The tests**: so it can find out whether a change actually worked

It can try, fail, read the error, and fix it, without you carrying messages back and forth.

The week 6 agent, with a project as its folder.

---

## The Loop, in a Project

1. Reads the related files
2. Edits three of them
3. Runs the program
4. Reads the error
5. Fixes it
6. Runs the tests and reports

In a chat, steps 3 to 5 are three round trips through you.

---

## Your Role

- **Specify**: say what it should do, and how you'll know it works.
- **Supervise**: read the plan, and build in small steps you can check one at a time.
- **Check**: run it, try to break it, and ask for explanations of anything you don't follow.

You're responsible for what you ship, including the parts you didn't write.
