## Git in Four Moves

- **commit**: save a snapshot of the project, with a message saying what changed
- **diff**: see exactly which lines changed since the last snapshot
- **revert**: undo a change by going back to an earlier snapshot
- **push**: send your commits to GitHub, as a backup and to share

**Small commits are your safety net.** Each one is a point you can return to.

## Reading a Diff

```diff
 function total(expenses) {
-  return expenses.length;
+  return expenses.reduce((sum, e) => sum + e.amount, 0);
 }
```

Minus: removed. Plus: added.

One line, inside `total`. A count became a sum.


---

## Questions to Ask of a Diff

- Is it the **size** I expected? A one-line fix shouldn't touch five files.
- Is it in the **places** I expected, given the feature I asked for?
- Was anything **deleted**, and did I ask for that?
- What should I ask about before I accept it?

When in doubt: "Explain this change in plain language." You don't need to read code to ask good questions about it.

## Small Commits

| | One big commit | One per working step |
|---|---|---|
| Something breaks | Which change? | The last one |
| Undo | Lose everything | Go back one |
| Review | Hundreds of lines | Readable |

Broken, and the fix isn't obvious? **Go back** and try again.

## Claude Code in VS Code

- Plan mode: `Shift+Tab` or `/plan`
- Permission modes: ask, accept edits, auto
- Instruction file: `CLAUDE.md` (or `AGENTS.md`)
- `/context`: what's filling the context window
- `/usage`: what you've used against your plan

## An Instruction File for a Project

```markdown
# Budget tracker
## Technology
- Plain HTML, CSS, JavaScript. No frameworks.
## How to run
Open `index.html` in a browser.
## Rules
- One feature at a time, then stop.
- Don't add dependencies without asking.
- I'm not a programmer. Explain each change.
```

## `/context` Is a Lesson in Itself

Run it on a fresh session, before you type anything:

- The system prompt and tool descriptions use tokens **before you type**.
- Instruction files and connectors have a **standing cost** on every message.
- Compaction (`/compact`) summarizes the conversation to free space, and discards detail.

Week 2's context window, made visible.

## A Working Rhythm

1. **Describe** one feature
2. **Plan**: read and edit
3. **Build**
4. **Run** it yourself
5. **Read the diff**
6. **Commit**

Then the next feature. The rhythm feels slow at first, and it's much faster than untangling five features at once.
