## Plugins

- A plugin is a **bundle** of skills, connectors, and other pieces, installed together.
- It's shared with a team as one unit, so everyone gets the same set.
- It's how organizations package "the way we do things" for their agents.

Think of a skill as one procedure, and a plugin as a team's whole playbook.

---

## Why Organizations Use Plugins

- **Consistency**: everyone follows the same procedure and uses the same template.
- **Onboarding**: a new hire installs it, and their agent already knows the team's procedures.
- **Updating**: change the plugin once, and everyone gets the new version.

Plugins are shared through **marketplaces**, which can be public or private to an organization.


---

## Read Before You Install

A skill is instructions an agent follows **with your files and permissions**.

- Consider the source
- Read the `SKILL.md`
- Look at the scripts
- Check what it connects to
- Try it on a copy, with approvals on

Before you share one: no personal details, no passwords.

---

## Skills in Chat vs in an Agent

| In chat | In an agent with a folder |
|---|---|
| Works on **uploaded copies** | Works on **the real files** |
| Instructions typed in settings | Instruction file **lives with the work** |
| Can't run your tests or tools | Can run scripts, tests, local tools |
| Results downloaded | Results saved in place |

Skills run in chat, but they're **limited** there.

---

## Where to Run a Skill

| The task | Better place |
|---|---|
| One pasted item into another | Chat is fine |
| Reads or writes many files | Agent with the folder |
| Must follow folder conventions | Agent |
| Runs a script or test | Agent |

Decide where it will run, and write for that place. A skill written for a folder will stumble in chat, where there's no folder to read.
